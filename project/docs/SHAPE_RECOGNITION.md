# 红色球体与方块：识别流程和实现边界

参考用户提供的《赛题解析二》PPT 第 21 页：MIPI → ISP → 颜色/形状特征 → 阈值判定 → 区域/坐标 → OSD → 显示。沿用实际工程的 DDR 帧缓存与 7 英寸 DSI 输出，没有改成 HDMI。

## 数据链路

```text
SC500CS → MIPI/CSI → 去马赛克 → 原有白平衡/手动色偏/提亮
       → 原有 DDR 完整帧缓存 → 1024×600 裁剪显示流
       → 红色分割 → 水平短游程过滤 → 单区域边界/面积/行描述
       → 消隐期轮廓分析 → 类别/坐标整帧锁存
       → 目标框旁的标签、黑框和中心十字 → 原有触摸 UI → DSI 屏
```

为了保留已经稳定的采集、白平衡及缓存链路，新增形状模块放在显示时钟域，使用已经白平衡处理过的图像。检测在任何标注/UI 前进行，自己的黑框、红色标签和中文字不会进入识别输入。自动页的开关沿用原来的配置位，控制与帧快照方式不变。

本版仍是一个主要红色目标。不是多目标检测器，也没有为每个独立物体分配连通域编号；每行统计一个红色候选区域。分离物体或明显不连续的区域会尽量降为 UNKNOWN，但不保证任意多个红色区域都能排除。不要用本版的一个外接框代表多个物体的正确分类结果。

## 可综合硬件实现

### 1. 颜色与候选区域

继承前版 RGB 判定：R≥80、R≥G+32、R≥B+24、2R≥3G、2R≥3B、G≤B+48。只累加每行至少 4 个连续红像素的游程，过滤孤立的短噪点。候选区域至少 200 个有效红像素、宽高各至少 12 像素，连续两个完整帧确认。

每行记录 `{存在标志, 最左X, 最右X, 有效红像素数}`，共 34 位；600 行为 20,400 位描述存储，内容在每一完整显示帧中覆盖。没有新增整帧 RGB 缓存。

### 2. 完整性和形状特征

只对完整帧内的候选区域分类。触及画面边缘、形状太小、行缺失、过于稀疏、严重偏心或上下明显不平衡时给出 UNKNOWN。分类最小宽高门限默认 48 像素；建议球体和方块的宽高达到 64～80 像素以上，留出轮廓分辨率。

统计区域面积、逐行外轮廓宽度、红色填充率、宽高比例、上下半区平衡及横向轮廓重心。用 16 段近圆宽度模板计算整体轮廓误差。球体高光造成的小范围内部白洞不直接破坏外轮廓，但大面积高光、暗边消失或遮挡仍可能无法分类。

### 3. 球体与方块区分

- **RED BALL**：宽高近似、区域面积及宽度模板接近圆形，同时轮廓具有持续弯曲，不能只用少量直线解释。不会仅凭“宽高相近”就判球。
- **RED CUBE**：两侧边界可由少量直线段拟合，整体近似凸的 4～6 个顶点轮廓，配合面积、填充率和比例门限。面向正面的方块、滚转后的方形轮廓，以及可见多个面的透视投影均纳入设计。
- **UNKNOWN**：找到了红色区域，但当前证据不足以区分上述两类。三角形没有专用类别；测试中的三角形会走 UNKNOWN，不显示 TRIANGLE。

直边分析采用带小栈的逐段扫描：读取行轮廓，检查相对端点连线的最大偏差，超出容差时分段。默认水平容差 `max(2, 宽度/40)`；忽略上下各两行的栅格端点，降低近水平边缘在像素化后产生的假拐点。每侧最多接受 4 段直线，超过后只有同时满足近圆条件的目标才能归为球体。近水平端部和透视会使顶点数近似，因此不把“4～6 段”当作三维几何证明。

只在垂直消隐期读取上一帧行描述。若有效图像开始时仍未完成，立即中止并显示 UNKNOWN，不在有效画面中途改变类别。类别在第一有效像素处锁存，此后整帧保持。

### 4. 标注布局

继承黑色 3 像素外接框和黑色中心十字。类别及坐标改为一条红底白字标签，如 `RED BALL ( 511, 299)`、`RED CUBE ( 508, 312)`；未确定时显示 `UNKNOWN (...)`。

标签优先置于目标框上方；目标过高则放到下方。右侧接近屏幕边缘时向左收回，设置页还会避开右侧 UI 面板。没有目标时，NO TARGET 放在画面下方中央附近，取消框和十字。没有固定在左上角的检测结果面板。

坐标采用屏幕有效区左上角原点，X=0～1023，Y=0～599，中心取外接框中心并向下取整。识别结果对应上一显示帧，运动时约滞后一帧。

## 必须理解的识别范围

这是针对球体和方块常见外观的单目规则分类。它没有深度传感器、多视角重建或通用物体识别网络，不能证明物体有体积。红色圆片、正方形纸片或外轮廓相同的其他物体，在相同投影下也可能得到相同类别。

上板先用饱和红色球、哑光红色方块、干净浅色背景和均匀光照测试，保留足够目标尺寸。方块可缓慢转动观察类别；过强阴影、高光、大遮挡、快速运动、背景同色干扰会降低稳定性。不要把合成仿真通过率当作实际摄像头识别率。

## 验证入口

`verification/generate_shape_fixtures.py` 生成独立测试输入：球体圆形投影、带内部高光的球体、较暗红色、从三维顶点做透视投影的不同姿态方块，以及三角形/细长椭圆/八边形/过小/截断/非红色/分离目标/空画面对照。fixture 是输入模型，不是摄像头照片。

`shape_classify_tb` 检查 23 个模型场景、边界/中心、类别和消隐不足时的降级。`shape_video_tb` 把分类、标签和真实 UI 叠加串联，核对帧确认、画面尺寸、同步延迟、标签位置和实际输出截图；旧的颜色、白平衡、色偏、触摸、遥测和缓存测试继续运行。
