# 红色纸面色块识别：SC500CS + 自动白平衡 + 7 英寸触屏

基于用户提供的 `lab_wb_blackfix_DSI_SC500_7inch.zip` 增加单色单目标识别。适用 PH1P35MDG324、SC500CS、1024×600 DSI + GT911 触屏。摄像头、白平衡算法、感光度、黑屏修复及帧缓存保护沿用基线。

## 上板与操作

1. 整包解压到短英文路径，例如 `C:/FPGA/red_target`。
2. 下载根目录 `DSI_RED_TARGET_SC500_7inch_compress.bit`，也提供普通 `.bit`。新功能必须使用本包新镜像。
3. 实时画面长按约 0.8 秒 → 白平衡设置 → 自动白平衡。
4. 点击右侧 **红色目标识别 / 关闭** 按钮，切换为 **开启**；按钮范围为屏幕 `600≤X<1000，400≤Y<472`。回退两次返回完整预览。
5. 将打印红色色块的白纸放入画面，保持白纸和色块清晰可见。连续两个完整显示帧满足条件后显示黑色 3 像素矩形框、黑色中心十字、`RED TARGET` 与中心坐标。移走目标后，下次结果更新显示 `NO TARGET`，取消框和十字，坐标行留空。
6. 开关默认关闭，回退页面会保留选择；预设/自定义模式暂停识别，回到自动模式恢复所记忆的开关状态。开关在显示帧边界生效，长按按钮只切换一次。

第一版只识别红色类别，不推断物体名称；背景中应只有一个主要红色区域。保持白纸可见可帮助原有自动白平衡工作。参数是初始值，需要结合打印颜色、光照和实物摄像头复测。

## 显示及坐标

- 坐标原点是 **1024×600 屏幕有效图像的左上角**，X 范围 0～1023，Y 范围 0～599，向右/向下增加。
- 检测范围包含整个显示图像，检测数据位于 UI、框线、文字叠加之前，不会把自身标注当成目标。
- 外接框采用首尾均包含的像素坐标；中心是 `(left+right)/2`、`(top+bottom)/2`，向下取整。示例 `X: 499 Y: 279`，数字固定宽度对齐。
- 摄像头原始画面为 1280×720，现有工程中心裁剪为 1024×600；如需换算到原图，X 加 128、Y 加 60。
- 检测结果属于上一显示帧。首次出现需两个完整合格帧，持续检测通常滞后一帧；快速移动时框会落后。无目标或不完整帧立即清除下一次发布的结果，不额外维持丢失框。
- 设置页右侧仍由 UI 覆盖，可能遮住框的一部分；回实时预览可看完整框。顶部/底部状态条保留。

## 算法与可调参数

`user_source/hdl_source/target/red_target_video.v` 提供可综合 Verilog 参数；修改实例参数后重新编译：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `R_MIN` | 80 | 红通道最小亮度 |
| `RG_MARGIN` / `RB_MARGIN` | 32 / 24 | R 至少高于 G / B 的差值 |
| `MIN_RUN` | 4 | 每行至少连续 4 个红像素才加入区域，参数应取 2～1024 |
| `MIN_PIXELS` | 200 | 通过短游程过滤后的最小红像素数 |
| `MIN_WIDTH` / `MIN_HEIGHT` | 12 / 12 | 外接框最小宽高，单位为显示像素 |
| `CONFIRM_FRAMES` | 2 | 首次确认的连续帧数，取 1～255 |
| `BOX_THICKNESS` | 3 | 黑框向目标内部的厚度 |

另外要求 `2R≥3G`、`2R≥3B`、`G≤B+48`，抑制灰白、黄橙及常见肤色干扰。比较使用扩展位宽，避免 8 位加法溢出。它是阈值颜色分类，不能保证拒绝所有红棕色/红色背景。孤立的 1～3 像素噪点会被过滤；多个足够大的红区域会合并成一个外接框，本版未实现连通域分离。

## 源码入口

| 文件 | 内容 |
|---|---|
| `target/red_target_detect.v` | 水平短游程过滤、面积及边界统计、逐帧确认、中心坐标 |
| `target/red_target_video.v` | RGB 判断、显示坐标、黑框/十字、状态与十进制坐标；所有视频信号共同经过 3 级寄存 |
| `target/target_ascii_font.v` | 英文/数字 5×7 字模，显示放大 2 倍 |
| `ui/wb_ui_control.v` | 自动白平衡页中的识别开关 |
| `ui/wb_ui_overlay.v` / `wb_ui_font.*` | 中文按钮、帧锁存状态 |
| `design_top_wrapper.v` | 23 位配置邮箱、检测 → 原有 UI → DSI；配置与视频同步延迟 |

上述源码路径相对 `user_source/hdl_source/`。没有增加整帧缓存，检测及叠加均运行于 DSI 显示时钟域。配置通过原有请求/应答邮箱跨时钟域传递。三个 TD 工程文件已登记新模块。时序约束仅为新增的 UI 邮箱第 22 位补齐已有的 held-payload 例外，没有修改时钟频率或放宽同步路径。

## 编译与验证

- TD 6.2.1 打开 `td_project/wb_ui_dsi.al`，内部工程名保留。
- 工程根目录运行 `./build.ps1`；默认 TD 安装路径为 `C:/APP2/ALTD`，可用 `-TdHome` 修改。最终时序不通过时脚本不会把新镜像复制到根目录。
- `./verification/run_sim.ps1` 重跑原有 18 项及新增 2 项仿真；可用 `-VivadoBin` 指定 Vivado 的 `bin` 路径。
- `verification/check_project.py --baseline-zip <原始压缩包>` 检查所有相对引用及基线保护。
- `BUILD_REPORT.md`、`build_evidence/` 和 `BUILD_MANIFEST.json` 记录本次验证、时序及交付文件哈希。再次编译后以新日志为准。
- `ui_preview/` 是真实 RTL 输出的合成测试场景，不是摄像头实拍。

本次环境没有连接实物开发板。仿真不能代替打印纸、现场光照、摄像头/屏幕物理链路的上板验证；请在白纸、绿色/蓝色对照块和目标移入移出三种场景复测。
