# 现版扩展：8×8 实时像素画、原图提亮、触屏六模式

基于上一版五模式负片工程，新增 8×8 像素画，改善原图亮度。摄像头仍为 SC500CS RAW10 1280×720，显示仍为 7 寸 DSI 的 1024×600 中心裁剪。

## 使用方法

将整个压缩包解压至短路径，例如 `C:/FPGA/pixel6`。沿用现版开发板、摄像头、DSI 触摸屏连接。在 BitWriter 选择 **PH1P35MDG324**，通过 JTAG/SRAM 下载工程根目录：

**`DSI_TOUCH6_PIXEL8_BRIGHT_SC500_7inch_compress.bit`**

同目录提供不带 `_compress` 的普通镜像。KEY1 复位回原图，KEY2/KEY3 沿用摄像头增益减/加。全屏任意位置点按切换：

**提亮原图 → Sobel 边缘 → 提亮原图＋OSD → 灰度 → 负片 → 8×8 像素画 → 提亮原图……**

| 编号 | 显示 | 从复位起点按次数 |
|---|---|---:|
| 0 | 提亮后的彩色原图 | 默认；第 6 次返回 |
| 1 | 原有 Sobel 白边黑底 | 1 |
| 2 | 提亮后的彩色图＋原有 Logo、文字和帧计数 | 2 |
| 3 | 原有灰度图 | 3 |
| 4 | 原有彩色负片 | 4 |
| 5 | 新增 8×8、256 色实时像素画 | 5 |

每次点按后全部手指离屏约 30 ms，再进行下一次。长按、拖动、增加手指不重复切换。模式在摄像头帧开始生效，经过原有 DDR 缓存显示，有数帧延迟；请等画面稳定后再切换。

## 像素画实现

每个 8×8 源图像块取左上角颜色，量化为 RGB332（红 3 位、绿 3 位、蓝 2 位，共 256 色），再复制到整块。量化输出通过位复制扩展回 RGB888，黑白端点完整保留。不会使用平滑插值。

1280×720 源画面对应 160×90 个色块，视频输出数据量、时序和屏幕分辨率保持原配置。显示中心裁剪从源坐标 (128,60) 开始，因此屏幕上、下边界会截取部分 8×8 色块，这是源图像网格与裁剪的正常结果。

处理位置在现有 AWB 之后、DDR 打包之前；每拍四个像素，8 像素宽的块占两拍。仅缓存一行 160 个 RGB332 色号，共 160 字节，并保存当前块色号；不增加整帧缓存或帧延迟。与原图、Sobel、灰度、负片支路一样只有一拍输出寄存，所有支路连续运行，切换后不需要额外预热。

## 原图提亮

现有 AWB 保留，本次先在它之后增加温和的亮度曲线；没有新增白平衡切换算法，也没有调整摄像头寄存器、DSI 背光或曝光参数。软件所说“原图”是 RAW10 经去马赛克和现有 AWB 后的彩色显示。

对 RGB 三通道使用同一条曲线，8 位输入 `x`：

```text
0 ≤ x < 64：    y = x + floor(x/2)
64 ≤ x < 192：  y = x + 32
192 ≤ x ≤ 255： y = x + floor((255-x)/2)
```

| 输入亮度 | 0 | 32 | 64 | 128 | 192 | 224 | 255 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 输出亮度 | 0 | 48 | 96 | 160 | 223 | 239 | 255 |

主要提亮暗部和中间亮度，增量最多 32；曲线单调，纯黑和纯白保持不变，中性灰仍然中性。它不会恢复原始曝光已丢失的细节，也不能代替后续色彩校准；实际强度需要结合你的屏幕和光照上板判断。

提亮应用于模式 0、模式 2 的视频底图及模式 5 的取色。灰度、负片和 Sobel 继续使用上一版 AWB 输出，因此这三种已有算法的输入与结果保持原定义。OSD 图形文字本身不经过提亮。

## 后续 UI 接口

完整模式链路仍为 3 位，保留编号 0～4，像素画使用 5，6/7 暂保留；非法编号在帧开始退回模式 0。当前仍由 `touch/touch_mode_cycle.v` 产生模式请求，现有邮箱、帧边界选择和 DDR 槽标签负责把完整编号传到屏幕侧。

后续 UI 可在系统时钟域替换模式请求来源，继续复用这套链路。此次不增加 UI 页面或新的触屏操作规则。

`isp_top` 的参数 `BRIGHTEN_ENABLE` 默认为 1；设为 0 并重新编译，可关闭原图/OSD/像素画的提亮。它目前是构建参数，不是运行时 UI 控件。像素画块大小本版固定为 8×8。

## 打开和重建

TD 6.2.1 打开 `td_project/touch6_dsi.al`，顶层 `design_top_wrapper`，目标 PH1P35MDG324，Speed -3。建议在短路径解压和构建，避免旧工具对长路径的限制。

```powershell
./build.ps1 -TdHome C:/APP2/ALTD
./verification/run_sim.ps1 -VivadoBin C:/APP2/VIVADO/2025.1/Vivado/bin
python ./verification/check_project.py
python ./verification/check_project.py --baseline-zip '上一版五模式负片工程压缩包完整路径'
```

Vivado 仅用于仿真，TD 用于安路 FPGA 构建。修改后应重新构建，随包报告与校验清单对应本次交付，重新编译后以新日志为准。

## 上板检查

1. 先检查默认原图的亮度、黑白物体和高光细节，观察运动画面是否连续。
2. 第五次点按进入像素画，移动物体检查实时更新，观察清晰方块和有限颜色。
3. 像素画模式长按数秒，确认不重复切换；松手后再点按应回原图。
4. 检查其余边缘、OSD、灰度和负片模式，KEY1 复位应回原图。

本环境未连接实体开发板、摄像头及触摸屏。构建和仿真结果见 `BUILD_REPORT.md`，实际显示效果与亮度强度仍需上述上板验收。
